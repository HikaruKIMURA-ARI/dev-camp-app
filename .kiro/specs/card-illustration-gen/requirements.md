# Requirements Document

## Project Description (Input)

カード生成時のイラストも Imagen 4 Fast Generate を使って生成したい

## Introduction

既存の参加者カード機能（`tyousei-ph2`）は、回答送信時に参加者名から Gemini で 7 属性のテキストカードを生成し、種族に対応した **絵文字** をアートスロット（`.yc-art-emoji`）に表示している。本仕様はこのアートスロットを、Imagen 4 Fast Generate で生成した **イラスト画像** に置き換えることを目的とする。

イラストは「AI が生成したモンスター名（カードの `title`）にちなんだ縦長（3:4）の絵」とし、テキストカードが AI 生成（Tier 1）に成功したときにのみ生成する。生成した画像は Cloudflare R2 に保存し、Workers の GET ルート経由で配信する。`participant_cards` には画像本体ではなく R2 オブジェクトキーのみを永続化し、取得 URL はそのキーから導出する。画像生成は **コスト保護のため月 50 枚を上限**（全イベント合計・JST 月初リセット）とし、上限到達・画像生成/取得失敗・Tier 2/3 への降格時はいずれも既存の絵文字表示へフォールバックして回答送信フローを必ず成功させる。Imagen 呼び出しには既存 `GEMINI_API_KEY` を再利用する。

## Boundary Context

- **In scope**:
  - Tier 1（AI）テキストカード生成成功時に、`title` を基にした Imagen 4 Fast Generate での 3:4 イラスト生成。
  - 月 50 枚（全イベント合計・JST 月初リセット）の生成上限管理と、上限到達時の絵文字フォールバック。
  - 生成画像の Cloudflare R2 への保存と、R2 オブジェクトキーの `participant_cards` への永続化、Workers GET ルート経由の配信。
  - カード表示（`CardView`）でのイラスト表示と、画像が無い場合の絵文字フォールバック。
  - イラスト生成のプロセス外依存をテスト時にスタブ化し、実 Imagen API 非依存でテストを完走させる仕組み。
- **Out of scope**:
  - 既存のテキストカード生成ロジック（7 属性・3 段フォールバック・サニタイズ）の仕様変更。
  - 回答編集（PUT）時のカード／イラスト再生成。
  - イラストのユーザー編集・再生成 UI・差し替え・削除。
  - SNS 共有 OGP、画像の永続外部 URL 配布、画像の CDN 最適化。
  - 既存テーブル（`events` / `event_options` / `event_responses` / `event_option_responses` / `event_custom_*`）のスキーマ変更。
- **Adjacent expectations**:
  - `tyousei-ph2` の「カード生成は失敗しても回答送信を失敗扱いにしない」原則を継承する。
  - 既存の `setCardGeneratorForTest` / `.env.test` 運用（プロセス外依存はモック、テストに API キー不要）と整合させる。

## Requirements

### Requirement 1: Tier 1 カードへのイラスト生成

**Objective:** イベント参加者として、自分のカードがモンスター名にちなんだイラスト付きで生成されてほしい。そうすれば出席表明がより豪華なガチャ体験になるから。

#### Acceptance Criteria

1. When 参加者が回答を送信しテキストカードが Tier 1（AI 生成）として確定し、かつ当月の生成枚数が上限未満のとき, the カードイラストサービス shall 確定した `title` を基にイラスト画像を 1 枚生成する。
2. When カードイラストサービスがイラスト生成を要求するとき, the カードイラストサービス shall Imagen 4 Fast Generate モデルを `@google/genai` SDK 経由で、アスペクト比 3:4（縦長）の 1 枚として呼び出す。
3. If テキストカードが Tier 2（テンプレ）または Tier 3（デフォルト）に確定したとき, then the カードイラストサービス shall イラスト生成を行わず、当該カードを画像なし（絵文字表示）として扱う。
4. The カードイラストサービス shall 1 回の回答送信あたり最大 1 回だけ Imagen API を呼び出す（リトライしない）。
5. The カードイラストサービス shall イラスト生成をテキストカード生成と同一の回答送信リクエスト内で同期的に完了させる。
6. When イラスト生成が成功したとき, the カードイラストサービス shall 生成画像を回答・テキストカードと同一トランザクションで永続化する。

### Requirement 2: イラストの保存（Cloudflare R2）

**Objective:** システム運用者として、生成したイラストを DB を肥大化させずに保存し URL で配信したい。そうすればカード表示が軽量に保たれ、Workers + R2 構成と整合するから。

#### Acceptance Criteria

1. When イラスト生成が成功したとき, the 画像ストレージ shall 生成画像を Cloudflare R2 のオブジェクトとして保存する。
2. When 画像が R2 に保存されたとき, the 画像ストレージ shall 当該画像を一意に識別する R2 オブジェクトキーを返す。
3. The カードイラストサービス shall 画像本体および完全な URL を `participant_cards` テーブルに格納せず、R2 オブジェクトキーのみを永続化する。
4. The 画像ストレージ shall 各 R2 オブジェクトを回答（`response_id`）ごとに一意に識別できるキーで保存する。
5. When 参加者がイラスト付きカードの画像を要求したとき, the システム shall Workers の GET ルートで R2 オブジェクトキーに対応する画像を R2 バインディングから読み出して返す。
6. While イベント詳細ページがカードを表示しているとき, the CardView shall 永続化された R2 オブジェクトキーから導出した Workers GET ルートの URL を参照してイラストを読み込む。

### Requirement 3: イラストの表示とフォールバック

**Objective:** イベント閲覧者として、各参加者のカードにイラストが表示され、無い場合も破綻なく見えてほしい。そうすれば一覧が常に見やすく保たれるから。

#### Acceptance Criteria

1. While カードがイラスト URL を保持しているとき, the CardView shall 既存の絵文字アートスロット（`.yc-art-emoji`）の代わりにイラスト画像を表示する。
2. If カードがイラスト URL を保持していないとき, then the CardView shall 既存の種族別絵文字（無ければ `✨`）を表示する。
3. The CardView shall イラスト表示時もレアリティ枠・属性・種族・ATK / DEF・フレーバーなど既存の 7 属性表示を維持する。
4. The CardView shall イラスト画像にスクリーンリーダー向けの代替テキスト（カードの `title` を含む）を付与する。
5. While ライトテーマまたはダークテーマが選択されているとき, the CardView shall いずれのテーマでもイラスト付きカードを破綻なく表示する。

### Requirement 4: 堅牢性とフォールバック（回答送信を失敗にしない）

**Objective:** イベント参加者として、イラスト生成に失敗しても回答送信そのものは必ず成功してほしい。そうすれば出欠調整の主機能が AI の不調に巻き込まれないから。

#### Acceptance Criteria

1. If Imagen API がタイムアウト・ネットワークエラー・5xx を返したとき, then the カードイラストサービス shall イラストなし（絵文字表示）でカードを永続化し、回答送信を成功させる。
2. If Imagen API がクォータ超過（403 相当）を返したとき, then the カードイラストサービス shall イラストなしでカードを永続化し、以降の同一プロセス内ではイラスト生成を抑止する。
3. If R2 への画像保存が失敗したとき, then the カードイラストサービス shall イラストなしでカードを永続化し、回答送信を成功させる。
4. The カードイラストサービス shall イラスト生成・保存の失敗を回答送信ハンドラに例外として伝播させない。
5. If `GEMINI_API_KEY`（または Imagen 用 API キー）が未設定のとき, then the カードイラストサービス shall Imagen を呼び出さず、すべてのカードを絵文字表示で扱う。
6. The カードイラストサービス shall イラスト生成の Imagen 呼び出しに既定 30 秒（テキストカード生成とは別の専用環境変数で上書き可能）のタイムアウトを設け、超過時はイラストなしで確定する。

### Requirement 5: 編集時のイラスト不変性

**Objective:** イベント参加者として、回答を編集してもカードのイラストが変わらないでほしい。そうすれば既存のテキストカードの振る舞い（編集で再生成しない）と一貫するから。

#### Acceptance Criteria

1. When 参加者が既存回答を編集（PUT）したとき, the カードイラストサービス shall イラストを再生成せず既存のイラストを維持する。
2. When 回答編集が完了したとき, the システム shall 当該回答に紐づく `participant_cards` のイラスト URL を変更しない。
3. While 回答編集のフラグメントが返却されるとき, the CardsCarousel shall 既存のイラスト集合をそのまま再表示する。

### Requirement 6: イラスト生成プロンプトとコンテンツ安全性

**Objective:** システム運用者として、生成画像が参加者名に起因する不適切な指示注入で汚染されないようにしたい。そうすれば公開イベントページに安全な画像のみが表示されるから。

#### Acceptance Criteria

1. The カードイラストサービス shall イラスト生成プロンプトを、AI が生成したカード属性（`title` を中核とし、必要に応じて `race` / `attribute` 等）から構築する。
2. The カードイラストサービス shall プロンプト中の参加者由来テキストを構造的な区切りで囲み、指示としてではなく値として扱う。
3. The カードイラストサービス shall イラストのスタイル（カードゲームのモンスター風など）とアスペクト比 3:4（縦長）を固定的に指定し、毎回一貫した作風・構図で生成させる。
4. Where Imagen 側が安全フィルタにより生成を拒否したとき, the カードイラストサービス shall これを生成失敗として扱い、絵文字表示へフォールバックする。

### Requirement 7: 環境設定とテスト分離

**Objective:** 開発者として、テスト・ローカル・本番でイラスト生成の有効/無効と差し替えを制御したい。そうすれば実 Imagen API・R2 に依存せずテストを完走でき、無料枠を無駄に消費しないから。

#### Acceptance Criteria

1. The カードイラストサービス shall Imagen のモデル名・タイムアウト・月次上限枚数等を環境変数で差し替え可能にする。
2. The カードイラストサービス shall Imagen 呼び出しに専用キーを新設せず、既存 `GEMINI_API_KEY` を再利用する。
3. While `bun test`（単体・統合）を実行しているとき, the カードイラストサービス shall 実 Imagen API および実 R2 を呼び出さず、差し替え可能なスタブを使用する。
4. The カードイラストサービス shall テスト時にイラスト生成器を差し替えるための setter（既存 `setCardGeneratorForTest` と同様の仕組み）を提供する。
5. While `bun run test:e2e`（Playwright）を実行しているとき, the システム shall 実 Imagen API を呼び出さず、決定論的なイラスト挙動（または絵文字フォールバック）でカードを表示する。
6. The システム shall テスト実行に Imagen 用 API キーおよび R2 認証情報を必要としない。
7. While ローカル開発（`bun run dev`、R2 バインディング非利用）で稼働しているとき, the カードイラストサービス shall R2 が利用できない場合でも回答送信を成功させ、絵文字表示へフォールバックする。

### Requirement 8: 月次生成上限（コスト保護）

**Objective:** システム運用者として、有料の画像生成コストを月単位で頭打ちにしたい。そうすれば想定外の課金を避けつつ、上限内ではイラスト体験を提供できるから。

#### Acceptance Criteria

1. The カードイラストサービス shall イラスト生成枚数の上限を全イベント合計で月 50 枚（環境変数で上書き可能）とする。
2. The カードイラストサービス shall 当月の生成枚数カウントを DB の月次カウンターとして永続化し、プロセス再起動・複数インスタンスをまたいでも一貫して集計する。
3. The カードイラストサービス shall 月次カウントの集計境界を JST の月初め（毎月 1 日 0 時）でリセットされる暦月単位とする。
4. When イラスト生成が成功し R2 への保存まで完了したとき, the カードイラストサービス shall 当月の生成枚数カウントを 1 加算する。
5. If 当月の生成枚数が上限に達しているとき, then the カードイラストサービス shall Imagen を呼び出さず、当該カードを Tier 1（AI 生成テキスト）のまま画像なし（絵文字表示）として永続化する。
6. While 月次上限に達しているとき, the カードイラストサービス shall 回答送信を成功させ、テキストカードの Tier 判定に影響を与えない。
